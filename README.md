# 立场之间 v2.2 · 政治价值与政策取向自测

正式站点：https://zz.sun2snow.dpdns.org/ 。网站由 GitHub Pages 托管，GitHub Actions 在所有检查通过后发布 `_site/`，CNAME 保持不变。Pages 的发布来源须选择 **GitHub Actions**；若仍从 main 分支根目录自动发布，就会绕过测试。

新版用更常见的中文措辞。问卷有 96 道基础题，根据各方面基础答案的分散程度，每方面可增加 4 道补充题，总共最多 40 道，都可以跳过。如果初步结果最接近中间主义，还会出现 10 道可跳过的澄清题。报告列出基础分和纳入有效补充答案后的当前分数；证据足够时，也会说明最接近哪种思想传统。方法链接均指向排版后的 HTML 页面。

问卷尚未用真人样本校准，也未验证阅读难度对应的年级、信度或效度。答案只在浏览器本地处理，进度须主动选择才会保存。网站不设账号，也没有分析追踪。

## 兼容

v2.2 改写了经济管理、公众参与、传统与生活、对外安全四个方面的部分题目，详见[题目修订记录](docs/题目修订记录.md)。新版只导入 v2.2 的答案，也不会覆盖或自动迁移旧版进度。旧版入口只显示停用说明，不再提供在线作答或导入；已下载的文件和浏览器里的旧进度不会被本版删除。未启用的补充题答案会随本版文件导出，但不计入当前分数。不同题库版本的分数不宜直接比较。

## 开发与复核

- 先运行 `npm run build`，再用 `python3 -m http.server 8765 --directory _site --bind 127.0.0.1` 预览实际发布内容。
- `node --test tests/*.test.mjs`：验证当前规则、版本隔离、存档竞态和输入校验。
- `npm ci && npx playwright install chromium`：按锁文件安装浏览器测试依赖。运行网页不需要这些依赖。
- `npm run build`：生成只包含网站资源的 `_site/` 发布目录。
- `SITE_ROOT=_site npm run test:e2e`、`SITE_ROOT=_site npm run test:audit`：在待发布版本上运行端到端测试和安全回归测试。
- `node scripts/score-cli.mjs answers-v2.json`：在本地生成报告；只接受 v2.2 答案，加 `--json` 输出结构化结果。
- `python3 scripts/revise-v22.py`：从冻结的 v2.1 题库与修订题干重建 v2.2。`python3 scripts/revise-bank.py` 仅重建历史 v2.1 题库。
- `python3 scripts/build-docs.py`：重建 HTML 文档和下载包。只有构建时需要 Python Markdown 包，运行网页不需要。

正式题库在 data.json。adaptive.mjs 决定何时加题，core.mjs 负责计分，ideology.mjs 负责归纳单一结果。前端视图和交互位于 app.js 与 ui/*.mjs。十维雷达图可切换三种视角，24 种参考画像可在弹窗中浏览；结果页可逐题查看各维度的作答，并跳回原题修改。页面还支持键盘快捷作答、浅色和深色外观、URL Hash 视图导航，以及进度未保存时的离页提醒。

修改题目或规则时，须更新版本并重新验证。更多说明见[计分及加题规则](docs/计分与解释规范.html)和[归纳方法](docs/最贴近意识形态规则.html)。


## 存档与隐私保护

答案只在本地处理。主动开启保存后，答案会以明文写入浏览器的网站数据，不会加密。保存需要在 HTTPS 或 localhost 下使用，并且浏览器须支持 Web Locks。即使写入失败、保存还没完成，或多个标签页发生冲突，离开页面时仍会提醒有答案未保存。浏览器或操作系统强制关闭时，不保证能显示提醒。

如果当前存档格式无效或版本不符，网站不加载其中的答案，也不允许普通保存或重置覆盖它。你可以下载原始文本备份，继续只在本页作答，或明确确认用本页答案替换原记录并开启保存。下载的备份可能包含敏感答案，请自行保管。若浏览器不允许读取存储，页面也不会写入或删除存档。

多个标签页使用同一个具名 Web Lock 排队写入，并核对存档的修订版本。一旦发现冲突，旧标签页会停止保存，提醒先导出答案再刷新，不会悄悄合并或覆盖。清除存档时，网站用一个不含答案的独立标记（`political-values-v22-local-epoch`）阻止旧标签页再次写入，并清空关联标签页的答案。重置会立即清空本页答案；在确认本地存档已删除前，页面会提示旧答案可能仍在设备上，并在离页时请求浏览器提醒。删除失败可重试，也可在浏览器设置中清除网站数据。清空最后一题但尚未成功保存时，同样有离页提醒。

## 发布与嵌入防护

CI 通过 npm 锁文件固定 Playwright 依赖，GitHub Actions 则固定到具体提交 SHA。测试任务只有读取权限。只有推送到 main 或在 main 上手动运行工作流，且 `test` 通过后，才会执行 `deploy`；PR 不会触发发布。部署任务使用 `queue: max` 保留等待中的任务，避免晚完成的旧提交顶掉已排队的新提交。轮到部署时，工作流再核对受测提交是否仍是 `main` 的最新提交；不是则跳过发布，查询失败也不发布。浏览器测试针对 `_site/` 运行，发布目录不包含 node_modules、测试数据或 CI 配置。

主站、旧版入口和方法文档在被嵌入时，由 `security.js` 提前隐藏。问卷不会初始化，也不会读取答案。GitHub Pages 不支持由仓库自定义 HTTP 响应头，因此这种前端拦截不能替代服务器级的 `frame-ancestors`。如果域名前有反向代理，仍应为主站、旧版入口和文档统一设置 `Content-Security-Policy: frame-ancestors 'none'` 与 `X-Frame-Options: DENY`。

## v2.1：澄清中间位置

v2.1 引入了 10 道可跳过的澄清题，v2.2 沿用这个机制。归纳规则 nearest-tradition-2.3 修正了浮点误差导致的同距排序，十维分数和参考坐标不变。初步结果最接近中间主义时，澄清题用于区分明确支持折中、持有混合立场和还不确定的情况，不改变十维分数。导出文件用单独的 clarifications 字段保存 C_D1—C_D10。详见 docs/最贴近意识形态规则.html。
